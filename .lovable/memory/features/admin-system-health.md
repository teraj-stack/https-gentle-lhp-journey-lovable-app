name: Admin System Health & Token Abuse Detection
description: Strona /admin/system-health z monitoringiem podejrzanych prób użycia tokenów (404 invalid + 429 rate-limit + 410 expired + 409 already_used) — alert dla IP ≥10 prób / 10 min
type: feature

Tabela `token_validation_failures` (RLS: service_role insert, admin SELECT) loguje wszystkie nieudane próby użycia tokena na endpoincie `update-booking-status`. Kolumny: `endpoint`, `reason` (CHECK: invalid_token | rate_limited | expired | already_used), `ip`, `user_agent`, `metadata` (jsonb, np. `tokenPreview`, `method`, `retryAfterSec`).

Edge function `update-booking-status` używa `EdgeRuntime.waitUntil()` (fire-and-forget) żeby nie blokować response — logowanie nie wpływa na latencję.

View `recent_token_abuse_ips` (security_invoker = on) agreguje IP z ≥10 nieudanymi próbami w ostatnich 10 min — to próg detekcji brute-force pokazywany w alercie na `/admin/system-health`.

Cleanup: funkcja `cleanup_old_token_failures()` usuwa wpisy >30 dni (do podpięcia pod cron).

UI: `src/pages/AdminSystemHealth.tsx` — 3 karty stats (total/24h/unique IPs) + tabela podejrzanych IP (auto-refresh 30s) + ostatnie 100 nieudanych prób z kolorowymi badge'ami per `reason`. Link z `AdminDashboard` (przycisk "System Health" z ikoną Activity).

Znana ograniczenia: rate_limited count w praktyce zawsze = 0, bo in-memory rate limiter w edge function jest per-isolate i Supabase fan-out praktycznie go obchodzi (zweryfikowane: 30/30 → 404). Realny sygnał alarmowy daje `invalid_token_count` (próby brute-force fake tokenami).

Scroll-to-row w tabeli "Top retry sources" używa wspólnego helpera `scrollRowIntoView(el, force=false)` zamiast natywnego `scrollIntoView({ block: "center" })` — natywna metoda ignoruje sticky page header (CSS var `--header-height` z Header.tsx) i potrafi schować górną część wiersza. Helper celuje w **środek bezpiecznej strefy** (między dolną krawędzią headera a dnem viewportu): `safeAreaTop = headerH + 16`, `safeAreaBottom = innerHeight - 24`, `desiredViewportTop = safeAreaTop + (safeAreaHeight - rowHeight)/2` — wiersz ląduje w środku widocznego obszaru, łatwy do zlokalizowania wzrokowo. Fallback gdy wiersz wyższy niż safe area → wyrównaj do safeAreaTop. Parametr `force=true` (klik badge'a numeru porządkowego, Enter/J/K, Next/Prev w nawigatorze) zawsze scrolluje — wizualne potwierdzenie intencji usera. `force=false` (auto-reveal w `revealRowInTable` po zamknięciu modala) pomija scroll gdy wiersz już w pełni widoczny w bezpiecznej strefie. Behavior: `smooth` domyślnie, ale auto-degradacja na `auto` (instant) gdy `prefers-reduced-motion: reduce` (a11y) lub gdy poprzedni scroll był <250ms temu (`lastScrollAtRef` — spam J/K przez autorepeat anulowałby smooth animacje, instant utrzymuje 1:1 sync z klawiszem). Używany w 4 miejscach: `revealRowInTable` (force=false), `scrollToNavigatorIndex` (force=true), `performJumpToMatch` (force=true), `jumpToMatchIndex` tryb modalny (force=true). **Logika obliczania `targetY` wyciągnięta do czystej funkcji `computeRowScrollTarget` w `src/lib/scrollHelpers.ts`** — komponent przekazuje `rect.top/height`, `scrollY`, `innerHeight`, `headerH`, `force` i dostaje `targetY: number | null` (null = pomiń scroll, wiersz już widoczny). Pokryte testem `src/lib/scrollHelpers.test.ts` (9 przypadków): wiersz na górze/środku/dole listy, fully-visible + force=false (skip), fully-visible + force=true (scroll), częściowo zasłonięty przez header, częściowo poniżej dolnej krawędzi, wiersz wyższy niż safe-area (fallback do safeAreaTop), custom buffer/bottomBuffer.

Pulse animation (`animate-jump-pulse`, 3 iteracje × 0.6s = 1.8s) na wierszu po skoku jest zarządzany przez wspólny helper `pulseRow(el, opts?)` — DRY zamiast 3× copy-paste (remove → reflow → add → setTimeout). Force-reflow przez `void el.offsetWidth` restartuje animację gdy klikam Next/Prev na ten sam wiersz. Per-element timer w `pulseTimersRef = useRef<WeakMap<HTMLElement, number>>()` — nowy pulse czyści poprzedni cleanup zanim ustawi nowy, więc szybki Next→Prev na ten sam wiersz nie ucina drugiej animacji o pozostałe ms ze starego timeoutu. Respektuje `prefers-reduced-motion: reduce` — pomija animację dla a11y. Opcja `{ focus: true }` ustawia focus na wierszu (`el.focus({ preventScroll: true })`) — wymaga `tabIndex={-1}` na `<TableRow>` i `focus:outline-none` (focus-ring nie nakłada się na nasz primary ring). Focus włączony tylko gdy modal zamknięty — `scrollToNavigatorIndex` (nawigator bar = po close modala) i `revealRowInTable` ("Pokaż w tabeli" → modal odmontowany przed scrollem). `performJumpToMatch` i `jumpToMatchIndex` (tryb modalny) NIE używają focus, żeby nie ukraść klawiatury z otwartego dialogu. Używany w 4 miejscach: `revealRowInTable` (focus=true), `scrollToNavigatorIndex` (focus=true), `performJumpToMatch` (focus=false default), `jumpToMatchIndex` tryb modalny (focus=false default).

**Wzmocnienie wizualne (v2):** keyframe `jump-pulse` używa teraz **podwójnego ringa** (inset 2px primary 0.95 + outer 6px primary 0.45 + halo 24px primary 0.35) + tła `primary/0.28` + subtelnego `scale(1.012)` w 50% klatce — wiersz wyraźnie „skacze" wzrokowo zamiast tylko zmieniać kolor. Po pulse'ie (~1.7s) `pulseRow` przełącza element na `animate-jump-afterglow` (2.4s, `forwards`) — trwały ring + tło które same wygasają, żeby user nie tracił z oczu „gdzie jestem" po zaniku głównej animacji. Łącznie ~4s wyraźnego sygnału. Drugi timer (`__afterglowTimer` na elemencie) jest osobno anulowany przy nowym pulse'ie obok `pulseTimersRef` — bez tego szybkie Next→Prev planowałyby dwa przejścia pulse→afterglow równolegle. Wiersz `isNavigatorActive` (po wygaśnięciu wszystkich animacji) ma teraz dodatkowo `ring-offset-2 ring-offset-background` + `shadow-[0_0_20px_-4px_hsl(var(--primary)/0.55)]` — trwały „glow" pokazujący który wiersz jest aktualnie aktywny w nawigatorze, wyraźniej odseparowany od tła ring-offsetem.

**Tryb wysokiego kontrastu (v3):** Toggle „HC focus ON/OFF" w toolbar tabeli „Top retry sources" (obok „Auto-reveal" / „Highlight scope"). Stan `highContrastFocus` persystowany w `localStorage` pod kluczem `admin-system-health.high-contrast-focus`, default OFF. Gdy ON, dwa wzmocnienia działają razem: (1) wiersz `isNavigatorActive` dostaje grubszy ring (ringWidthPx + 2), wyższe tło `bg-primary/30`, mocniejsze halo oraz dodatkowy `outline outline-2 outline-offset-[-4px] outline-foreground/70` — warstwa primary+foreground daje kontrast i na jasnych, i na ciemnych motywach. (2) `pulseRow` dodaje klasę `jump-hc` na wierszu przed startem animacji; CSS w `src/index.css` definiuje keyframes `jump-pulse-cfg-hc` / `jump-afterglow-cfg-hc` (czyta CSS vars przez var()) i nadpisuje animacje przez selectory `.jump-hc.animate-jump-*`. Klasa `jump-hc` jest dodawana razem z resetem klas animacji i czyszczona w cleanup timerze — nigdy nie wycieka między skokami. Tryb pomijany dla `prefers-reduced-motion: reduce`.

**Konfigurowalny styl focusu (v4):** Popover „Styl focusu" w toolbar (obok „HC focus") z 3 sliderami: (1) **Czas afterglow** 800–6000ms (default 2400), (2) **Grubość ringa** 1–6px (default 2; HC dodaje +2), (3) **Intensywność glow** 0–100% (default 55, mapowane na opacity 0.25–0.80 i blur 20–44px). Stan `focusPrefs` (typ `FocusPrefs`) persystowany w `localStorage` pod kluczem `admin-system-health.focus-style-prefs` jako JSON. Walidacja przez `clampNum(v, min, max, fallback)` zabezpiecza przed NaN/string/poza zakresem przy hydratacji. Przycisk „Reset" przywraca `FOCUS_PREFS_DEFAULTS`. **Aplikacja preferencji**: (a) Aktywny wiersz (`isNavigatorActive`) używa inline `style={activeRowStyle}` (memo z `useMemo`) z dynamicznym `box-shadow` zależnym od `highContrastFocus` (klasy CSS robią tylko `bg`, `outline` i `transition` — bez statycznego `ring-N`/`shadow-[...]`, żeby uniknąć konfliktu specificity). (b) `pulseRow` ustawia inline CSS vars na elemencie (`--jump-ring-w`, `--jump-glow-blur`, `--jump-glow-spread`, `--jump-glow-opacity`, `--jump-afterglow-duration`) czytając z `focusPrefsRef.current` (latest values bez przebudowy callbacka). Po cleanup'ie (1700ms + afterglowMs + 100ms) inline vars są usuwane, żeby DOM zostawał czysty. **CSS**: `index.css` definiuje 4 keyframes (`jump-pulse-cfg`, `jump-afterglow-cfg`, `jump-pulse-cfg-hc`, `jump-afterglow-cfg-hc`) używające `var(--jump-* , fallback)` i nadpisuje statyczne klasy z `tailwind.config.ts` przez selectory `.animate-jump-pulse:not(.jump-hc)` / `.jump-hc.animate-jump-pulse` etc. Czas trwania afterglow odczytywany przez animation-duration z `var(--jump-afterglow-duration, 2400ms)` — slider działa od razu na kolejnym Next/Prev bez reloadu.
